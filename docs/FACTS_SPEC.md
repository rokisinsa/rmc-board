# 事実の構造化（日本語）— 1試合1ファイル
入力のJSONに書かれている内容だけを使う。新しい事実・数字を足さない、推測しない。書かれていない項目は unavailable に理由を書く。
英語は自然な日本語にする（チーム名・選手名はカタカナまたは一般的な表記。自信がなければ原文のまま）。

出力: data/facts/<match_id>.json （UTF-8、下の形）
{
 "match_id": "...",
 "data_as_of": "<入力の data_as_of>",
 "left": {"name": "左側（入力の対戦カードの左）", "ranking": "順位・ランキング・成績を短く（例：33勝11敗・第1シード）",
          "form": [ {"date": "9/26", "opp": "相手", "score": "3-1", "res": "W|L|D", "note": "大会名など短く（任意）"} ],   // 新しい順。日付不明なら "—"
          "form_summary": "直近の流れを1行（例：直近5試合4勝1敗）",
          "lineup": ["先発・欠場・ロスター情報を1項目1行"] },
 "right": { 同じ形 },
 "h2h": [ {"date": "2026-09-13", "event": "大会・ラウンド", "score": "York 26-12 Wigan のように勝者がわかる形", "winner": "left|right|draw"} ],  // 新しい順
 "h2h_summary": "通算などを1行",
 "venue": "会場・ホーム/アウェイ（1行）",
 "esports": {"format":"BO3","lan_online":"...","map_pool":"...","veto":"...","patch":"...","map_h2h":"..."}   // eスポーツのみ、なければ省略
 "risks": ["1項目1行"],
 "missing": ["取れなかった情報を1項目1行"],
 "unavailable": {"h2h": "理由", "form": "理由"}   // 空にした項目の理由
}
入力の文章に試合ごとのスコアがなく「〜に勝った」程度なら score は "—"、res は分かる範囲で入れる。
